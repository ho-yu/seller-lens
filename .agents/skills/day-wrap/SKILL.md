# day-wrap

저장소의 `docs/days/dayNN.md`가 원본이고, 노션 개발 일지는 **그 내용과 정확히 같은 사본**이다 (저장소 → 노션 단방향).
Day 번호 하나로 모든 것이 대응한다. **Day 번호는 장 번호와 같다** (1과목 Day05부터. 8장 = Day08).

| 노션 | 저장소 |
|---|---|
| `DayNN - <한 문장>` 페이지 | `docs/days/dayNN.md` |
| 본문의 실습·반영 파일 | `labs/dayNN/`, `src/` |
| 속성 `기능` | 일지의 `기능` 줄, `docs/FEATURES.md`의 해당 기능 기록 |
| 속성 `git` | 태그 `dayNN` (그날 끝난 시점) |

설정값(GitHub 저장소, 노션 위치)은 같은 폴더의 `config.json`에서 읽는다.

## 두 가지 모드

| 요청 | 하는 일 |
|---|---|
| "DayNN 기록", "오늘 정리" | 1~3단계만: 일지 작성·갱신, 노션 반영(상태 `진행 중`). 커밋·푸시 안 함 |
| "마무리" | 1~5단계 전부: 일지 확정 → 커밋 → `dayNN` 태그 → 푸시 → 노션 반영(상태 `완료`) |

푸시는 사용자가 "마무리"나 "푸시"라고 했을 때만 한다. 마무리는 강이 끝났을 때 한다.

## 1. Day 번호와 범위 정하기

- Day 번호는 그날 한 장의 번호다 (1과목 8장 = `day08`). `docs/days/dayNN.md`가 이미 있고 상태가 `진행 중`이면 이어 쓰고, 없으면 새로 만든다.
- 하루에 한 장을 끝낸다. 한 장이 다음 날로 넘어가도 Day 번호를 새로 만들지 않고 같은 일지에 이어 쓴다 (날짜는 `시작한 날 ~ 끝난 날`).
- 건너뛴 장은 번호도 건너뛴다 (9장을 건너뛰면 `day08` 다음은 `day10`). 강의와 상관없는 작업(데이터 수집, 환경 설정)은 그날 하던 장의 일지에 적는다.
- 2과목부터의 번호는 1과목이 끝날 때 사용자와 정한다.
- 번호는 두 자리(`day01`). 날짜는 오늘 날짜.
- 그날 범위: 가장 최근 `day*` 태그 이후의 커밋 + 커밋 안 된 변경(`git status`, `git diff`) + 이번 대화 내용.
- 그날 범위에 없는 내용은 적지 않는다. 다른 날 한 일은 그날 일지에 둔다.

## 2. 일지 작성 (`docs/days/_template.md` 형식)

- 제목: `# DayNN - <그날 배운 내용을 한 문장으로>`. 이 줄이 노션 페이지 제목이 된다.
- **🔑 복습 키워드**가 핵심이다.
  - 3~5개. 키워드 하나에 한 문장. 사용자가 나중에 헷갈릴 만한 개념 위주로 고른다.
  - **학습 내용(강의 개념, 실습 개념, 데이터·평가 개념)만** 고른다. 환경 설정, 도구, 기록·진행 방식은 키워드로 넣지 않는다.
  - 키워드마다 관련 파일 경로를 적는다 (줄 번호는 적지 않는다). 경로가 실제로 있는지 확인한다.
- "🔧 바뀐 것"에는 그날 바뀐 `labs/`, `src/` 파일을 한 줄씩 적는다.
- "💬 질문"에는 **학습 내용과 관련된 질문만** 면접 질문과 답 형식으로 적는다 (`**Q. ...**` 아래 `- A. ...`). 환경·도구·진행 방식 질문은 적지 않는다. 답에는 이번에 확인한 숫자 예시를 넣는다. 없으면 `- 없음`.
- 일지는 짧게 쓴다. 키워드 3~5개, 질문 5개 이하.
- 파일 이름은 항상 백틱으로 감싼다 (`FEATURES.md`). 그냥 쓰면 노션이 `.md`를 도메인으로 보고 `http://FEATURES.md` 링크로 바꾼다.
- 머리말의 `기능:` 줄에 그날 만들거나 바꾼 기능을 적는다 (F1~F9, 공통). `src/`나 공통 설정을 건드리지 않은 날은 `없음`.

### 2-1. `docs/FEATURES.md` 갱신

그날 `기능`에 적은 기능마다:
- "기능별 기록"의 해당 기능 아래에 `- DayNN: <그날 만들거나 바꾼 것, 주요 파일>` 한 줄을 **맨 아래에** 추가한다 (이미 그날 줄이 있으면 고친다).
- "요약" 표의 상태(`예정` → `진행 중` → `완료`)와 관련 Day 목록을 갱신한다.
- 일지의 `기능`과 FEATURES.md의 Day 기록이 서로 맞는지 확인한다.

## 3. 노션 반영

`config.json`의 `notion.devlog_data_source`에서 `Day` = N인 페이지를 찾는다 (없으면 만든다).

**속성**

| 속성 | 값 |
|---|---|
| 주제 | 일지 제목에서 `# `를 뺀 것 (`DayNN - <한 문장>`) |
| Day | N |
| 날짜 | 일지의 날짜 |
| 과목 | `준비` · `딥러닝 실전 & 프롬프트` · `데이터 수집 & API` · `LangChain` · `RAG` 중 해당 |
| 장 | 일지의 장 (예: `1장 2강`) |
| 기능 | 일지의 `기능` 줄 (`F2 리뷰 자동 태깅`처럼 노션 옵션 이름 그대로, `없음`이면 비움) |
| 키워드 | 복습 키워드를 쉼표로 나열 |
| 상태 | 기록 모드 `진행 중`, 마무리 모드 `완료` |
| git | `dayNN` (+ 짧은 커밋 해시, 푸시 전이면 `(푸시 전)`) |
| GitHub | `https://github.com/<repo>/tree/dayNN` |
| 마지막 반영 | 오늘 |

**본문은 일지와 같게 한다.**

- 맨 위: 원본 안내 콜아웃 "원본: 저장소 `docs/days/dayNN.md`. 아래 ✍️ 내 메모 구역은 반영할 때 덮어쓰지 않습니다."
- 그 아래: 일지의 섹션을 **같은 순서, 같은 문장으로** 옮긴다. 요약하거나 문장을 바꾸지 않는다. 마크다운 표는 노션 표로, 목록은 목록으로만 바꾼다.
- 맨 아래: `## ✍️ 내 메모` 구역. 이미 페이지가 있으면 이 제목 아래는 절대 수정하지 않는다. 그 위쪽만 바꾼다.

**반영 후 검증**: 노션 페이지를 다시 읽어 일지와 섹션 수, 키워드 수, 표의 행 수가 같은지 확인한다. 다르면 고친다.

## 4. 커밋·태그 (마무리 모드)

1. 변경 내용을 사용자에게 요약해 보여준다. `.env`나 민감한 파일이 섞여 있지 않은지 확인한다.
2. 커밋: `DayNN: <한 문장>`
3. 태그: `git tag dayNN`.
   - 이미 태그가 있고 **아직 푸시 전**이면 `git tag -f dayNN`으로 옮긴다.
   - 이미 푸시된 태그는 옮기지 않는다. 추가 변경은 다음 Day에 기록한다.

## 5. 푸시 (마무리 모드)

```bash
git push origin main
git push origin dayNN
```

- 원격 저장소가 없거나 인증이 실패하면 멈추고 사용자에게 알린다. 강제 푸시는 하지 않는다.
- 푸시 후 노션 페이지의 상태를 `완료`, git 속성을 커밋 해시로 바꾸고 마지막 반영일을 갱신한다.
- 끝나면 노션 페이지 링크와 커밋·태그를 한 줄로 알려준다.
