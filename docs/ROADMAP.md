# sellerlens 로드맵

> 상품 리뷰로 소싱 판단의 근거를 정리해 주는 나만의 리뷰 분석기. 리뷰 분류는 직접 수집한 리뷰로 내가 학습시킨 모델(F12)로 한다. 목적과 결과물 모습은 [PLAN.md](PLAN.md).
> KANT 강의(딥러닝 실전 & 프롬프트 엔지니어링 → 데이터 수집 & API 서버 → LangChain → RAG 기초/심화)를 단계별로 직접 구현하며 만든다.
> 기능별 진행 상황은 [FEATURES.md](FEATURES.md)에 기록한다. (작성: 2026-10-02, 개정: 2026-11-20 소싱 판단용으로 방향 변경, 내 분류기 F12를 핵심으로)

## 공통 원칙

- **판단은 사람이 한다.** 도구는 소싱을 추천하거나 판정하지 않는다. 판단에 쓸 근거를 정리해 보여 준다.
- **숫자는 코드가 센다.** 별점 분포, 건수, 비율, 추이, 마진은 코드로 계산하고 LLM은 읽고 묶는 일만 한다.
- **근거를 남긴다.** 요약 항목마다 근거 리뷰를 붙이고, 근거가 없으면 쓰지 않는다.
- **측정한다.** 내가 라벨 붙인 평가셋으로 개선 전후를 숫자로 비교한다.
- **평가셋은 학습에 섞지 않는다.** 섞으면 점수가 부풀려져 내 모델이 좋아졌는지 알 수 없다.
- **개인정보는 넣지 않는다.** 원본의 `이름`, `리뷰어번호`는 정제 단계에서 지운 뒤 LLM에 보낸다. 로컬 LLM(Ollama)을 기본으로 쓴다.

## 기능 목록

### 핵심

| ID | 기능 | 쓰는 장면 | 관련 강의 |
|---|---|---|---|
| F1 | 리뷰 통합·정제 | 상품별로 수집한 엑셀을 넣으면 하나의 표준 데이터로 합친다 (중복·빈 본문·개인정보 제거, 상품·옵션·작성일 정리) | 데이터 수집 4장 · RAG 2장 |
| F2 | 리뷰 태깅 | 리뷰마다 `감성 / 좋은 점 유형 / 나쁜 점 유형 / 근거 문장`을 JSON으로 붙인다. 이 결과를 내가 검수해 F12의 학습용 정답으로 쓴다. 나쁜 점 예: 품질·내구성, 사이즈, 사용성, 소재·냄새, 배송·포장, 가격. 좋은 점 예: 성능, 가성비, 디자인, 사용 편의 | 딥러닝 실전 5~7장 · LangChain 2·3·5장 |
| F12 | 내 리뷰 분류기 | 검수한 정답으로 분류기를 학습해 리뷰 → 좋은 점·나쁜 점 유형을 분류한다. v0 별점 기준선 → v1 TF-IDF + 로지스틱 회귀 → v2 임베딩 + 로지스틱 회귀. 평가셋 200건으로 LLM 태깅과 비교한다 | 딥러닝 실전 1~2장(손실, 학습) · 6장(평가) · RAG 4장(임베딩) · 8장(평가) |
| F5 | 상품 리뷰 리포트 | 상품 하나의 별점 분포, 감성 비율, 좋은 점·나쁜 점 Top과 대표 리뷰, 확인할 점(5점인데 불만, 최근 추이, 옵션별 차이)을 한 장으로 본다 | 딥러닝 실전 8장(Tool Calling) · LangChain 4장 · RAG 6장(Citation) |

### 확장

| ID | 기능 | 쓰는 장면 | 관련 강의 |
|---|---|---|---|
| F6 | 리뷰 근거 검색 | "코팅 벗겨진다는 리뷰 보여 줘"처럼 물으면 상품·별점·옵션·기간 조건으로 걸러 원문을 보여 준다 | RAG 4~7장 (임베딩, Qdrant 필터, Hybrid, 리랭킹) |
| F10 | 상품 비교 | 후보 2~3개의 별점 분포와 좋은 점·나쁜 점을 한 표로 비교한다 | F5 결과 활용 · 데이터 수집 7장 |
| F11 | 금액 계산 | 원가, 판매가, 수수료, 배송비를 넣으면 마진과 마진율을 계산한다. LLM 없이 코드로 | 딥러닝 실전 8장(도구) · 데이터 수집 5~7장(API) |
| F9 | 리뷰 어시스턴트 | 한 질문창에서 답한다. 통계·금액 질문("코팅 불만 몇 %?", "2만 원에 팔면 마진은?")은 계산 도구로, 근거 질문은 검색으로 자동 분기한다 | 딥러닝 실전 8장 · LangChain 7·10장 · RAG 9장 2강 |

### 제외 (2026-11-20)

| ID | 기능 | 제외한 이유 |
|---|---|---|
| F3 | 대응 우선순위 큐 | 판매 중인 상품의 리뷰에 대응하는 기능이라 소싱 판단과 맞지 않는다. "5점인데 불만"은 F5의 확인할 점으로 옮겼다 |
| F4 | 리뷰 답글 초안 | 판매를 시작한 뒤에 필요한 기능이다 (Day05 답글 프롬프트 실습 기록은 남긴다) |
| F7 | CS 문의 답변 초안 | 판매를 시작한 뒤에 필요하고, 정책·FAQ 문서가 없다 |
| F8 | 판매 소구점 추출 | F5 리포트의 "좋은 점"에 흡수했다 |

### 운영 품질 (모든 기능 공통)

| 항목 | 내용 | 관련 강의 |
|---|---|---|
| 안정성 | timeout, retry, fallback 모델. 2천 건 일괄 태깅 중 실패한 리뷰만 다시 처리 | 딥러닝 실전 10장 · 데이터 수집 8장 · LangChain 9장 |
| 관측 | 토큰, 지연시간 로그, tracing | 딥러닝 실전 10장 2강 · LangChain 8장 |
| 출력 검증 | Pydantic 스키마 검증, 실패 시 재시도 | 딥러닝 실전 7장 · LangChain 5장 |
| 평가 | F2·F12: 내가 라벨 붙인 리뷰 200건 / F6: 검색 질문 평가셋, Hit@k, Recall@k | 딥러닝 실전 6장 · RAG 8장 |

### 강의에 있지만 우선순위가 낮은 것

| 항목 | 낮게 둔 이유 | 활용 아이디어 |
|---|---|---|
| 멀티모달 (딥러닝 실전 9장, RAG 9장 4강) | 리뷰 원본에 사진 파일이 없고 `사진수`만 있다 | 사진 리뷰를 수집하게 되면 파손·실물 차이를 확인한다 |
| 청킹 (RAG 3장) | 리뷰는 대부분 한두 문장이라 나눌 것이 거의 없다 | 긴 리뷰만 나누면 되는지 확인하는 정도로 쓴다 |
| GraphRAG (RAG 9장 3강) | 리뷰처럼 짧고 독립적인 문서에서는 효과가 작다 | 리뷰가 많이 쌓인 뒤 전체 주제 요약 실험용 |

## 추후 진행 (강의 범위 밖)

| 기능 | 가치 | 추후로 미룬 이유 |
|---|---|---|
| 리뷰 자동 수집 | 엑셀을 직접 만들지 않아도 된다 | 크롤링은 약관 위험이 있고 강의는 공공 API 기준이다 |
| 웹 화면 | 리포트를 보기 좋게 본다 | 강의는 API 서버까지라 당분간 CLI와 Swagger UI로 대신한다 |
| 관심 상품 리뷰 변화 알림 | 새 불만이 늘면 알 수 있다 | 스케줄러와 메신저 연동은 강의에서 다루지 않는다 |
| 판매 후 운영 기능 (F3·F4·F7) | 소싱한 상품의 리뷰 대응 | 실제로 판매를 시작한 뒤에 다시 본다 |
| 영구 DB, 배포 (Docker, 클라우드) | 여러 기기에서 쓴다 | 강의 범위 밖이다. 개인용 로컬 실행으로 시작한다 |
| LLM 파인튜닝, LangGraph 멀티 에이전트 | 품질·자동화 | 라벨 데이터가 부족하고 강의 범위 밖이다. "나만의 모델"은 F12 분류기로 한다 |
