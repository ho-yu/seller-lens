# sellerlens 로드맵

> 셀러가 리뷰와 고객 문의를 빠르게 처리하도록 돕는 개인용 도구.
> KANT 강의(딥러닝 실전 & 프롬프트 엔지니어링 → 데이터 수집 & API 서버 → LangChain → RAG 기초/심화)를 단계별로 직접 구현하며 만든다.
> 기능별 진행 상황은 [FEATURES.md](FEATURES.md)에 기록한다.
> 강의 범위 판단은 노션 강의 목차 기준이다. (작성: 2026-10-02)

## 공통 원칙

- **사람이 최종 확인한다.** 답글, CS 답변, 문구는 모두 "초안"이고 등록은 셀러가 직접 한다.
- **개인정보는 넣지 않는다.** 원본의 `이름`, `리뷰어번호`는 정제 단계에서 제거한 뒤 LLM에 보낸다. 로컬 LLM(Ollama)을 기본으로 쓴다.
- **근거를 남긴다.** 분류, 요약, 답변에는 근거가 된 리뷰나 문서를 함께 붙인다. 근거가 부족하면 답하지 않는다.
- **측정한다.** 평점 라벨과 직접 만든 평가셋으로 개선 전후를 숫자로 비교한다.

## 기능 목록 (강의 범위 안)

| ID | 기능 | 셀러 업무에서 쓰는 장면 | 관련 강의 |
|---|---|---|---|
| F1 | 리뷰 통합·정제 | 상품별, 기간별로 내려받은 엑셀을 넣으면 하나의 표준 데이터로 합친다 (중복·빈 본문 제거, 개인정보 제거, 메타데이터 정리) | 데이터 수집 4장 · RAG 2장 |
| F2 | 리뷰 자동 태깅 | 리뷰마다 `감성 / 불만 유형 / 긴급도 / 근거 문장`을 JSON으로 붙인다. 불만 유형 예: 배송, 파손, 품질·내구성, 사이즈·호환, 사용성, 소재·냄새, 가격, CS | 딥러닝 실전 5~7장 · LangChain 2·5장 |
| F3 | 대응 우선순위 큐 | 오늘 확인할 리뷰만 긴급도 순으로 본다. **평점은 높은데 내용에 불만이 있는 리뷰**(평점·내용 불일치)도 따로 잡아낸다 | F2 결과 활용 · 딥러닝 실전 6장(평가) |
| F4 | 리뷰 답글 초안 | 리뷰 유형에 맞는 판매자 답글 초안을 만든다. 응답 정책을 지킨다: 보상 확약 금지, 사실과 다른 내용 금지, 정해진 톤 | 딥러닝 실전 5장 2강(응답 정책) · 7장 |
| F5 | 상품 리뷰 리포트 | 상품·기간·옵션별 평점 분포, 불만 유형 순위, 추이, 대표 리뷰 인용을 한 번에 정리한다. 집계는 코드로 하고 LLM은 해석과 요약만 맡는다 | 딥러닝 실전 8장(Tool Calling) · LangChain 4장 |
| F6 | 리뷰 근거 검색 | "열에 녹는다는 리뷰 있어?", "네이비 옵션 사이즈 불만만 보여줘"처럼 물으면 상품, 평점, 옵션, 기간 조건으로 걸러서 원문과 출처를 보여준다 | RAG 4~7장 (임베딩, Qdrant 필터, BM25+Dense 하이브리드, 리랭킹) |
| F7 | CS 문의 답변 초안 | 상품 상세 설명, 교환·반품 정책, FAQ를 근거로 고객 문의 답변 초안을 쓴다. 출처를 표시하고, 근거가 부족하면 "담당자 확인 필요"로 보류한다 | RAG 3장(청킹) · 6장(Citation, 보류) · LangChain 7장(대화 맥락) |
| F8 | 판매 소구점 추출 | 긍정 리뷰에서 고객이 실제로 칭찬한 포인트와 표현을 뽑아 상세페이지·광고 문구 소재로 쓴다. 근거 리뷰를 함께 남기고 과장 표현은 금지한다 | 딥러닝 실전 5~7장 |
| F9 | 셀러 어시스턴트 (통합 질의) | 하나의 질문창에서 답한다. 통계 질문("지난달 파손 불만 몇 건?")은 집계 도구로, 근거 질문은 RAG로 자동 분기한다 | 딥러닝 실전 8장 · LangChain 7·10장 · RAG 9장 2강(Agentic RAG) |

### 운영 품질 (모든 기능 공통)

| 항목 | 내용 | 관련 강의 |
|---|---|---|
| 안정성 | timeout, retry, rate limit, fallback 모델 | 딥러닝 실전 10장 · 데이터 수집 8장 · LangChain 9장 |
| 관측 | 토큰, 비용, 지연시간 로그, tracing | 딥러닝 실전 10장 2강 · LangChain 8장 |
| 출력 검증 | Pydantic 스키마 검증, 실패 시 복구·재시도 | 딥러닝 실전 7장 · LangChain 5장 |
| 평가 | F2: 평점 라벨 대비 정확도 / F6·F7: Golden Dataset, Hit@k, Recall@k, RAGAS | 딥러닝 실전 6장 · RAG 8장 |

### 강의에 있지만 우선순위가 낮은 것

| 항목 | 낮게 둔 이유 | 활용 아이디어 |
|---|---|---|
| 멀티모달 (딥러닝 실전 9장, RAG 9장 4강) | 리뷰 원본에 사진 파일이 없고 `사진수`만 있다 | 셀러가 가진 상세페이지 이미지에서 스펙과 주의사항을 추출해 F7의 근거 문서로 만든다 |
| GraphRAG (RAG 9장 3강) | 리뷰처럼 짧고 독립적인 문서에서는 효과가 작다 | 리뷰가 많이 쌓인 뒤 전체 주제 요약 실험용으로 쓴다 |
| 딥러닝 실전 1~4장 | 이론(손실 함수, Attention, RLHF) 위주라 기능과 바로 연결되지 않는다 | 모델 선택과 프롬프트 설계의 배경지식으로 쓴다 |

## 추후 진행 (강의 범위 밖)

| 기능 | 셀러 가치 | 추후로 미룬 이유 |
|---|---|---|
| 판매 채널 리뷰 자동 수집 (오픈마켓 판매자 API 연동) | 엑셀을 내려받지 않아도 된다 | 판매자 API 승인과 인증이 필요하고, 강의는 공공 API 기준이다. 크롤링은 약관 위험이 있어 하지 않는다 |
| 답글·CS 답변 자동 등록 | 등록까지 자동화 | 외부 채널에 쓰기 권한이 필요하고, 잘못 게시될 위험이 있다. 초안 품질이 검증된 뒤에 검토한다 |
| 웹 대시보드 UI | 비개발자도 쓸 수 있다 | 강의는 API 서버까지라 당분간 Swagger UI로 대신한다 |
| 신규 부정 리뷰 알림, 주간 리포트 자동 발송 | 놓치는 리뷰가 없어진다 | 스케줄러와 메신저 연동은 강의에서 다루지 않는다 |
| 사진 리뷰 이미지 분석 | 파손 사진 등을 자동으로 확인 | 원본 데이터에 이미지가 없다 |
| 분류 모델 파인튜닝 | 비용이 줄고 속도가 빨라진다 | 학습용 라벨 데이터가 부족하고 강의 범위 밖이다 |
| 경쟁 상품 리뷰 비교 | 시장 조사 | 타사 리뷰 수집에 약관 문제가 있다 |
| 영구 DB, 로그인, 배포 (Docker, 클라우드) | 여러 셀러나 기기에서 쓸 수 있다 | 강의 범위 밖이다. 개인용 로컬 실행으로 시작한다 |
| LangGraph 기반 멀티 에이전트 | 복잡한 업무 자동화 | LangChain 10장 3강에서 한계만 짚고 넘어간다 |
