## 🔑 복습 키워드

| 키워드 | 한 문장 | 파일 |
|---|---|---|
| messages | LLM API에는 `{"role": ..., "content": ...}` 목록을 보내고, 답은 `response.choices[0].message.content`에서 꺼낸다 | `labs/day05/dl_ch05_llm_api.py` |
| System Prompt | system 메시지에 모델의 역할과 규칙을 담고, user 메시지에는 이번 입력(리뷰)을 담는다 | `labs/day05/dl_ch05_llm_api.py` |
| temperature | 점수를 temperature로 나눈 뒤 softmax를 하므로, 낮을수록 1등 단어가 압도적이라 답이 같아지고 높을수록 2·3등도 뽑혀 답이 달라진다 | `labs/day05/TASKS.md` |
| temperature와 품질 | temperature는 답이 얼마나 달라지는지만 정하고 얼마나 좋은지는 정하지 않는다. T=0에서도 어색한 한국어가 나온다 | `labs/day05/TASKS.md` |
| 프롬프트 비교 측정 | 프롬프트를 고칠 때는 같은 리뷰·같은 temperature로 10번씩 돌려 숫자로 비교하고, 같은 프롬프트도 1~5개로 흔들려 차이가 1~2개면 의미를 두지 않는다 | `labs/day05/dl_ch05_llm_api.py` |
| 바닥 효과 | 지표가 0에 닿으면(V1·V2 모두 탓 0/30) 더 비교할 수 없어서 문장 수·구체성 같은 다른 지표가 필요하다 | `labs/day05/dl_ch05_llm_api.py` |
| 예시의 부작용 | 프롬프트에 좋은 답글 예시를 1개 넣으면 문장은 안 베껴도 모양을 따라 해서 낮은 temperature에서 같은 답이 반복된다 | `labs/day05/dl_ch05_llm_api.py` |
| 균형 데이터와 자연 분포 | 균형 데이터는 클래스별 재현율·F1을 재는 용도, 자연 분포 데이터는 실제 비율(부정 약 10%)에서의 정밀도를 보는 용도라 둘 다 필요하다 | `data/processed/reviews.csv` |
| 평가셋 분리 | 정확도를 재는 리뷰는 프롬프트 튜닝이나 few-shot 예시에 쓴 리뷰와 겹치면 안 된다 | `labs/day05/dl_ch05_llm_api.py` |

## 💬 질문

1. **Q. 답글 초안의 temperature는 높을수록 좋은가?**
   - A. 아니다. 같은 리뷰로 10번씩 받아 "사용자 탓" 표현을 세니 T=0.3에서 2개, 0.8에서 3개, 1.2에서 5개로 늘었다. 서로 다른 답은 세 값 모두 10/10이라, 다양성을 위해 1.2까지 올릴 필요가 없었다. 다만 10번 측정이고 단어 포함 여부로 센 거라 확정은 아니고, 정밀한 평가는 6장에서 한다.
2. **Q. temperature를 낮추면 왜 답이 같아지는가?**
   - A. 후보 점수 부정 2, 중립 1, 긍정 0을 temperature로 나눈 뒤 softmax를 한다. T=1이면 부정 66%, T=0.5면 점수 차이가 벌어져 87%, T=2면 차이가 좁아져 51%다. T=0은 1등만 고르는 극한이다.
3. **Q. 같은 리뷰를 temperature 0으로 두 번 보내면 항상 같은 답인가?**
   - A. 거의 그렇다. 처음 실행에서는 앞 문장은 같고 뒤가 "불편을"과 "불편함을 겪으셨다는 점을"로 갈렸고, 다시 실행하니 두 답이 똑같았다. 중간 단어 하나가 갈리면 뒤 문장이 따라 바뀐다.
4. **Q. 4점 리뷰 "요리하고 나면 누렇게 변하고 냄새가 나는게 정상인가요??"와 "전원 콘트롤 부분은 잘 보이지 않아 자르던지 해야 할듯"을 모델은 뭐라고 분류하는가?**
   - A. 둘 다 부정이다. 평점은 4점이어도 내용에 불만이 있으면 부정으로 기운다. Day04에서 본 "점수는 높은데 불만인 리뷰"와 같은 현상이다.
5. **Q. 답글 초안이 어색한데 temperature만 고치면 좋아지는가?**
   - A. 한계가 있다. T=0에서도 "진심으로 양해드립니다" 같은 어색한 말이 나왔다. 작은 모델(4B)이고 프롬프트가 짧아서(두 문장, 환불 약속 금지만 있음) 생기는 문제라, 고객 탓 금지·예시를 넣는 프롬프트 개선과 셀러의 확인이 필요하다.
6. **Q. 프롬프트에 "고객 탓은 하지 않는다"를 넣으면 효과가 있는가?**
   - A. 같은 리뷰로 temperature 0.3·0.8·1.2에서 10번씩 재니 V0(규칙 없음)는 탓 답이 1+3+1=5/30, V1(탓 금지)은 0/30이었다. 방향은 일관되지만 V0 T=1.2가 이전 측정에서는 5개였는데 이번에는 1개라 확정은 아니다. 탓 단어 목록에 "주의"가 있어 셀러의 사과("주의하겠습니다")도 걸릴 수 있다는 한계도 있다.
7. **Q. 좋은 답글 예시를 넣은 V2가 V1보다 나은가?**
   - A. 탓은 둘 다 0/30이라 이 지표로는 비교할 수 없다. V2는 T=0.3에서 서로 다른 답이 10/10에서 7/10으로 줄었고, 따로 뽑은 10개 중 6개가 같은 문장이었다. 두 문장 규칙은 V2 10/10, V1 9/10으로 조금 더 지켰지만 표본이 작다. 그래서 V1을 유지하고 V2는 실험으로 남겼다.
8. **Q. 모델이 전부 "긍정"이라고만 답해도 정확도가 높게 나오는가?**
   - A. 기존 486건(부정 47건)에서는 439/486=90%, 새 2,076건(부정 658건)에서는 1,418/2,076=68%다. 부정 비율이 낮을수록 아무것도 안 해도 정확도가 높아서, 부정 리뷰의 재현율·F1을 같이 봐야 한다.
9. **Q. 정확도 평가용 리뷰는 평점별로 어떤 비율로 모아야 하는가?**
   - A. 1점 15%, 2점 15%, 3점 25%, 4점 20%, 5점 25%를 제안한다. 지금은 3점이 67건(정제 후 0건), 4점이 167건으로 가장 부족하다. 부정·중립·긍정 각 100건의 균형 평가셋과 평점 필터 없이 최신순으로 모은 200~300건의 자연 분포 평가셋을 따로 두고, 100건 정도는 직접 읽고 라벨을 붙인다.
