## 1. MSE ◀ 지금

**핵심**
- 예측과 정답의 **차이를 제곱해 평균** 낸다: `MSE = mean((y_pred - y_true)²)`
- 제곱하는 이유는 두 가지다. ① 음수 오차와 양수 오차가 서로 지워지지 않는다. ② 큰 오차를 더 크게 벌한다 (오차 2배 → loss 4배).
- 정답과 똑같이 예측하면 0이다. 0보다 작아질 수 없다.

**✍️ 직접 작성**

| 함수 | 무엇을 위한 함수인가 | 반환 |
|---|---|---|
| `mse_loss(y_pred, y_true)` | 리뷰 본문만 보고 평점(1.0~5.0)을 예측하는 회귀 문제의 loss | 숫자 하나 (0 이상) |

**정답 출력**

```
=== 키워드 1. MSE (평점 예측) ===
실제 평점: [5. 4. 1. 3.]
좋은 예측 [4.8 4.1 1.5 3. ] → MSE 0.0750
나쁜 예측 [3. 5. 4. 3.] → MSE 3.5000

--- 오차가 2배가 되면 loss는 4배 ---
오차 1 → MSE 1
오차 2 → MSE 4
오차 4 → MSE 16
```

**설명해 보기**
1. MSE가 오차를 그냥 더하지 않고 **제곱**하는 이유 두 가지는?
2. 나쁜 예측에서 MSE 3.5 중 가장 크게 기여한 리뷰는 어느 것이고, 왜 그럴까?

<details>
<summary>모범 답</summary>

1. ① 오차 `-1`과 `+1`을 그냥 더하면 0이 되어 "완벽하다"고 착각한다. 제곱하면 둘 다 1이 된다. ② 큰 오차를 더 크게 벌한다. 오차 1은 1, 오차 4는 16이다.
2. 세 번째 리뷰(실제 1점을 4점으로 예측). 오차가 3이라 제곱하면 9로, 네 리뷰의 제곱 오차 합 14(4 + 1 + 9 + 0) 중 9를 차지한다. 1점 리뷰를 4점으로 잘못 보는 것은 셀러에게 가장 위험한 실수이기도 하다.

</details>

## 2. BCE와 clip

**핵심**
- 이진 분류(정답 0 또는 1)의 loss다: `BCE = -mean[ y·log(p) + (1-y)·log(1-p) ]`
- 정답이 1이면 `log(p)`만, 정답이 0이면 `log(1-p)`만 남는다. 즉 **정답 쪽 확률에 -log**를 씌운 것이다.
- 정답 쪽 확률이 0에 가까워질수록 loss가 **급격히** 커진다 (p = 0.1 → 2.30, p = 0.01 → 4.61).
- 확률이 정확히 0이면 `log(0) = -inf`가 된다. 그래서 `np.clip`으로 `[eps, 1 - eps]` 범위로 자른다.
- 실무(PyTorch)에서는 확률이 아니라 logits를 받는 `BCEWithLogitsLoss`를 쓴다. Day02의 log-softmax와 같은 이유다.

**✍️ 직접 작성**

| 함수 | 무엇을 위한 함수인가 | 반환 |
|---|---|---|
| `binary_cross_entropy(probs, targets, eps)` | "이 리뷰가 부정 리뷰인가?"(1 = 부정)를 판별하는 문제의 loss | 숫자 하나 (0 이상) |

**정답 출력**

```
=== 키워드 2. BCE와 clip (부정 리뷰 판별) ===
정답:      [1. 0. 1. 0.]
좋은 예측 [0.9 0.1 0.8 0.2] → BCE 0.1643
나쁜 예측 [0.1 0.9 0.3 0.8] → BCE 1.8546

--- 정답이 1(부정)일 때, 예측 확률 p에 따른 loss ---
p=0.99 → BCE 0.0101
p=0.9  → BCE 0.1054
p=0.5  → BCE 0.6931
p=0.1  → BCE 2.3026
p=0.01 → BCE 4.6052

--- clip: 확률이 정확히 0이나 1인데 틀린 경우 ---
BCE 27.6310  ← clip이 없으면 -log(0) = inf
```

**설명해 보기**
1. 정답이 0(부정 아님)인 리뷰에서 BCE 공식의 어느 항이 남을까? 예측 확률 `p = 0.9`면 loss가 클까 작을까?
2. `np.clip`은 무엇을 막아 줄까? 27.63이라는 값은 어디서 나왔을까?

<details>
<summary>모범 답</summary>

1. `y = 0`이면 앞 항 `y·log(p)`가 0이 되어 `-log(1-p)`만 남는다. `p = 0.9`는 "부정일 확률 90%"라고 말한 것이니 틀린 예측이고, `-log(0.1)` = 2.30으로 loss가 크다.
2. 확률이 정확히 0이나 1일 때 `log(0) = -inf`가 되어 loss가 `inf`가 되는 것을 막는다. clip으로 0을 `1e-12`로 바꿨기 때문에 `-log(1e-12)` ≈ 27.63이 나온다. 아주 크지만 유한하다.

</details>

## 3. Cross Entropy

**핵심**
- 다중 분류의 loss다. 리뷰마다 **정답 클래스의 log 확률에 마이너스**를 붙인다: `L_i = -log p(정답)`
- BCE를 클래스 여러 개로 넓힌 것과 같다. 정답 클래스 확률이 1에 가까우면 0, 0에 가까우면 커진다.
- 확률이 아니라 **logits를 받아서** Day02의 `stable_log_softmax`로 log 확률을 바로 구한다. 그래서 큰 logits에서도 overflow·underflow가 없다.
- 리뷰마다 정답 칸 하나만 꺼내려면 `log_probs[행 번호들, 정답 번호들]`처럼 **행과 열을 짝지어** 꺼낸다.
- **예측(argmax)이 같아도 loss는 다를 수 있다.** loss는 "얼마나 확신하고 맞혔는지"까지 본다.

**✍️ 직접 작성**

| 함수 | 무엇을 위한 함수인가 | 반환 |
|---|---|---|
| `cross_entropy_per_sample(logits, targets)` | [부정, 중립, 긍정] 감성 분류의 loss를 리뷰마다 계산. **2장에서 분류기를 학습시킬 때 다시 쓴다** | 리뷰별 loss, shape `(N,)` |

**정답 출력**

```
=== 키워드 3. Cross Entropy (감성 3분류) ===
logits:
[[ 2.   1.  -0.5]
 [ 0.2  0.3  1.5]]
정답: ['부정', '긍정']
log 확률:
[[-0.3715 -1.3715 -2.8715]
 [-1.7534 -1.6534 -0.4534]]
리뷰별 loss: [0.3715 0.4534]
평균 loss:   0.4125

--- 정답(부정) logit을 키우면 ---
부정 logit 0.0 → loss 1.4644
부정 logit 2.0 → loss 0.3715
부정 logit 4.0 → loss 0.0591
부정 logit 8.0 → loss 0.0011

--- 예측은 같아도 loss는 다르다 (강의안 11절 오해 2) ---
확신 [ 4.  0. -1.]: 예측 부정, loss 0.0247
애매 [ 1.   0.9 -1. ]: 예측 부정, loss 0.7130

--- 큰 logits (강의안 9절) ---
[1000, 1001, 1002], 정답 긍정 → loss 0.4076  ← log-softmax라 overflow 없음
```

**설명해 보기**
1. 리뷰별 loss `[0.3715 0.4534]`는 log 확률 표의 어느 칸에서 나왔을까?
2. "확신"과 "애매" 리뷰는 둘 다 부정으로 맞혔는데 loss가 30배 가까이 차이 난다. 왜일까? 이게 Day02의 어떤 이야기와 이어질까?
3. 정답 logit을 키울수록 loss가 줄어든다. 2장에서 "학습"이 하는 일을 이걸로 설명해 보면?

<details>
<summary>모범 답</summary>

1. 리뷰 1은 정답이 부정(0번)이라 1행 0열의 `-0.3715`, 리뷰 2는 정답이 긍정(2번)이라 2행 2열의 `-0.4534`. 여기에 마이너스를 붙인 값이다.
2. loss는 맞혔는지만이 아니라 정답 클래스의 **확률**을 본다. 확신 리뷰는 부정 확률이 약 0.98, 애매 리뷰는 약 0.49라서 `-log`가 크게 다르다. Day02 키워드 1의 "argmax는 같아도 확률이 있어야 확신 정도를 안다"와 같은 이야기다.
3. 학습은 loss가 작아지는 쪽으로 모델 파라미터를 고치는 것이다. Cross Entropy에서 loss가 작아지려면 정답 클래스의 logit이 커져야 하므로, 학습은 "정답 클래스 점수를 올리는" 방향으로 모델을 바꾼다.

</details>

## 4. 정답 표현: class index와 one-hot

**핵심**
- 같은 정답을 두 가지로 적을 수 있다. **class index**는 리뷰마다 번호 하나 `(N,)`, **one-hot**은 리뷰마다 클래스 수만큼의 0/1 `(N, C)`.
  - 예: 정답 `[0, 2]` ↔ `[[1, 0, 0], [0, 0, 1]]`
- one-hot으로 Cross Entropy를 구하면 `-Σ (one_hot × log_probs)`인데, 정답 자리만 1이라 결국 정답 log 확률만 남는다. 그래서 **두 방식의 loss가 같다.**
- 라이브러리마다 받는 형식이 다르다. PyTorch `CrossEntropyLoss`는 보통 class index를 받는다. shape이 틀리면 에러가 나거나 조용히 틀리니 형식을 먼저 확인한다.

**✍️ 직접 작성**

| 함수 | 무엇을 위한 함수인가 | 반환 |
|---|---|---|
| `to_one_hot(targets, num_classes)` | 정답 번호를 one-hot으로 바꾼다. 두 표현이 같은 정보임을 확인한다 | one-hot, shape `(N, C)` |

**정답 출력**

```
=== 키워드 4. 정답 표현: class index와 one-hot ===
class index: [0 2]  shape (2,)
one-hot:
[[1. 0. 0.]
 [0. 0. 1.]]  shape (2, 3)
one-hot으로 계산한 loss: [0.3715 0.4534]
index로 계산한 loss:     [0.3715 0.4534]  ← 같다
```

**설명해 보기**
1. 리뷰 486개, 클래스 3개일 때 class index와 one-hot의 shape은 각각?
2. one-hot으로 계산해도 loss가 같은 이유는?

<details>
<summary>모범 답</summary>

1. class index는 `(486,)`, one-hot은 `(486, 3)`.
2. one-hot은 정답 자리만 1이고 나머지는 0이다. `one_hot × log_probs`를 하면 정답 자리의 log 확률만 남고 나머지는 0이 되므로, 행마다 더하면 정답 log 확률 하나가 된다. index로 정답 칸 하나를 꺼낸 것과 같다.

</details>

## 5. reduction

**핵심**
- loss는 먼저 **리뷰마다 하나씩** 만들고, 그다음 하나로 줄인다. 이 방식을 reduction이라고 한다.
  - `none`: 줄이지 않고 그대로 `(N,)`. 어떤 리뷰가 loss가 큰지 볼 때 쓴다.
  - `mean`: 평균. 가장 많이 쓴다 (PyTorch 기본값).
  - `sum`: 합.
- 같은 리뷰를 2배로 늘리면 `mean`은 그대로이고 `sum`은 2배가 된다. 학습에서는 이 차이가 **파라미터를 고치는 크기**(2장의 gradient)에도 영향을 준다 (강의안 11절 오해 4).

**✍️ 직접 작성**

| 함수 | 무엇을 위한 함수인가 | 반환 |
|---|---|---|
| `reduce_loss(sample_losses, reduction)` | 리뷰별 loss를 `none` / `mean` / `sum`으로 줄인다 | `none`이면 `(N,)`, 나머지는 숫자 하나 |

**정답 출력**

```
=== 키워드 5. reduction ===
none: [0.2 0.8 0.5]
mean: 0.5
 sum: 1.5

--- 같은 리뷰를 2배로 늘린 배치 ---
mean: 0.5000 → 0.5000  ← 그대로
sum:  1.5000 → 3.0000  ← 2배
```

**설명해 보기**
1. `mean`과 `sum` 중 배치 크기(한 번에 넣는 리뷰 수)를 바꿔도 loss 크기가 비슷하게 유지되는 것은? 왜 그게 편할까?
2. `none`은 sellerlens에서 어디에 쓸 수 있을까?

<details>
<summary>모범 답</summary>

1. `mean`. 리뷰 수로 나누기 때문에 배치가 32개든 128개든 loss 크기가 비슷하다. 그래서 배치 크기를 바꿔도 학습률 같은 설정을 다시 맞출 필요가 줄어든다.
2. 리뷰별 loss가 큰 리뷰는 모델이 크게 틀린 리뷰다. 이런 리뷰만 골라 보면 라벨이 잘못됐는지(예: 5점인데 내용은 불만), 모델이 어떤 리뷰를 어려워하는지 알 수 있다. F3 "5점인데 불만인 리뷰" 찾기와도 이어진다.

</details>

강의안보다 한 걸음 더 나간 응용이다. 하지 않아도 Day03은 끝난다.

<details>
<summary>펼치기</summary>

- **BCE with logits:** 확률 대신 logit `z`를 받는 BCE를 만든다. sigmoid를 거치지 않고 `max(z, 0) - z·y + log(1 + exp(-|z|))`로 계산하면 overflow가 없다. 확률 버전과 결과를 `np.allclose`로 비교한다.
