## 한 문장 핵심

LLM API는 `messages`(역할 + 내용 목록)를 보내고 답 문자열을 받는다. **System Prompt**는 모델의 역할과 규칙을, **user**는 이번 입력(리뷰)을 담고, **temperature**는 답이 얼마나 매번 달라질지 정한다.

## ✍️ 함수 (작성 순서는 파일 주석)

| 함수 | 목적 | 줄 수 |
|---|---|---|
| `build_messages` | System Prompt + 리뷰 → `[system 메시지, user 메시지]` | 1~4줄 |
| `ask_llm` | messages를 보내고 답 문자열만 꺼낸다 | 2줄 |

## 실행 전 예상

1. 4점 리뷰 두 개(냄새 질문, "전원 부분이 안 보여 잘라야 할듯")를 모델은 뭐라고 분류할까?
2. temperature 0으로 답글 초안을 두 번 받으면 두 답글은 같을까?
3. temperature 1.2로 두 번 받으면?

<details><summary>정답</summary>

1. 둘 다 부정. System Prompt에 "중립"이 있어도, 불만이 조금이라도 있으면 부정으로 기우는 경향이 있다. 6장에서 정확도를 잴 때 이 차이가 드러난다.
2. 거의 항상 같다. 1등 단어만 고르기 때문이다. 다만 아주 가끔 한두 단어가 다를 수 있다 (실제로 한 번 "불편을" / "불편함을"이 달랐다).
3. 다르다. 2·3등 단어도 뽑혀서 문장이 매번 바뀐다. 사용법 탓을 하는 등 규칙에 어긋난 답글이 나오기도 한다.

</details>

## 한 문장으로 답하기

**감성 분류와 답글 초안에서 temperature를 각각 어떻게 둘까? 왜?**

<details><summary>모범 답</summary>

감성 분류는 0에 가깝게 둔다. 같은 리뷰에 매번 같은 답이 나와야 집계와 평가가 된다. 답글 초안은 0.7 안팎으로 조금 높여 표현을 다양하게 하되, 너무 높으면 규칙을 어기는 답이 늘어나므로 셀러가 확인한다. (같은 리뷰로 10번씩 재 보니 "사용자 탓" 표현이 T=0.3에서 2개, 0.8에서 3개, 1.2에서 5개였고, 서로 다른 답은 세 값 모두 10/10이었다. 10번 측정이라 확정은 아니고 6장에서 다시 잰다.)

</details>
